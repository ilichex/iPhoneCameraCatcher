# Захват Ableton — разбор исправления

Проверено 18 ноября 2026 года. Исправление находится в коммите db1d06b и релизе v0.2.0.

## Что мешало

- В Info.plist отсутствовал NSAudioCaptureUsageDescription. Apple требует этот ключ для Core Audio Tap. Разрешение на микрофон и разрешение на системный звук выдаются отдельно.
- Тап был добавлен в приватный агрегат без явного основного устройства. В исправлении выбранный аудиовыход включён как основной источник часов. Физические входы исключены из описания, а при чтении берутся последние буферы каналов тапа, чтобы не захватить сухой вход Scarlett.
- Начало WAV определялось временем вызова делегата, а не временем первого видеокадра. На macOS 15.2+ теперь используется startPTS, преобразованный из synchronizationClock сессии в host clock. Перед первым аудиобуфером добавляется соответствующая пауза.
- Ошибки записи WAV только печатались в лог, а временный WAV удалялся даже при ошибке объединения. Теперь ошибка попадает в результат, а WAV при неудаче остаётся рядом с видео.
- Временный отладочный код преобразовывал уровень звука в Int без проверки бесконечности. Такая диагностика могла завершить приложение на значении -infinity. Код удалён.

Эти изменения проверялись вместе. Отдельного эксперимента, который доказал бы единственную причину исходной тишины, не проводилось. Основная подтверждённая ошибка конфигурации — отсутствие обязательного ключа разрешения. Не приписывай весь результат одному изменению агрегата.

## Как устроен рабочий путь

Scarlett → дорожка Ableton с мониторингом и эффектами → Main/Master 1/2 → выбранный выход Scarlett → Core Audio Tap → временный WAV → FFmpeg → MOV с одной стереодорожкой.

В приложении выбрать тот же выход, что в Ableton, и «Только звук программ (Ableton)». Режим смешивания микрофона и программ добавляет сухой микрофон поверх обработанного сигнала. Тап захватывает все программы на выбранном выходе. Мониторинг через Scarlett сохраняется, muteBehavior установлен в unmuted.

WAV хранит Float32 с частотой тапа. Итоговый MOV содержит PCM signed 24-bit, стерео, с частотой входного WAV. Видео переносится через stream copy. apad/atrim подгоняют конец аудио к длине видео.

## Что проверено

- Сборка приложения, подпись и DMG.
- Тест объединения с разными сигналами в микрофонной и программной дорожках. Итоговое аудио совпало с программной дорожкой, видеопоток — с исходным.
- Живой захват выхода динамиков MacBook из QuickTime вместе с камерой iPhone. MOV длиной 5,2 секунды содержал ProRes и PCM24 stereo. В двух аудиоканалах обнаружен тестовый тон 880 Гц.
- Пользователь подтвердил работу с Ableton после обновления.

Во время нашей живой проверки Scarlett был отключён, Ableton закрыт. Самостоятельного испытания длинного дубля с проектом Ableton под нагрузкой не проводилось.

## Ограничение синхронизации

Сейчас host time используется для начала WAV. Последующие буферы дописываются по числу семплов. Код не выравнивает каждый буфер по host time и не обнаруживает пропущенные интервалы. Поэтому гарантировать отсутствие накопленного рассинхрона под нагрузкой нельзя.

Компенсация дрейфа агрегата согласует часы внутри аудиоустройства. Она не доказывает синхронность аудио с видео. apad/atrim меняют только конец дорожки, без исправления рассинхронизации внутри дубля.

Следующая содержательная проверка — запись 10–20 минут под реальной нагрузкой Ableton с хлопками в начале и в конце. Постоянный сдвиг и нарастающее расхождение измерять отдельно. Для надёжности нужны непрерывные временные отметки, учёт пропущенных аудиобуферов и контроль роста очереди. В realtime callback сейчас есть NSLock и выделение памяти, что требует пересмотра при высокой нагрузке.
